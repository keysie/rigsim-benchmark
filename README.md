# rigsim-benchmark

Hardware measurements of real machines, taken unattended by a bootable USB stick, published as open data.

Plug the stick into a machine, boot from it, walk away: it measures the CPU, memory and every GPU (low-level probes,
llama.cpp, Blender), stores the results on the stick and powers the machine off. Nothing is written to the
machine's own disks, and no serial numbers are kept.

- **Data table:** https://keysie.github.io/rigsim-benchmark/ — every run, filterable, with links to its raw files
- **Raw data:** [`results/runs/`](results/runs), one folder per run; layout in [`results/README.md`](results/README.md),
  versioned format and compatibility rules in [`results/FORMAT.md`](results/FORMAT.md)
- **The stick:** [`stick/README.md`](stick/README.md) — what it measures, how to build, flash and use it

The data feeds [rigsim](https://github.com/keysie/rigsim), a simulator for local AI hosts, but stands on its own.
Once a day, rigsim's newest engine release predicts every run it has not seen yet; the data page shows each
measured value with rigsim's prediction and its deviation, earlier releases' predictions on hover
([`predictions/README.md`](predictions/README.md)).

## What the data does and does not promise

Everything that can influence a result is recorded in the run: the exact version of every tool and component
(`manifest.json`, and per step in `run.json` → `tools`), and every decision the stick made while being built or
while measuring — fallbacks, skipped steps and why, overrides, dropped build targets, the exact command lines.
Runs are never changed after publication, and there is no list of known errors. Judging whether a result is
affected by a bug in some version is up to whoever uses the data, from what the data records.

## Contributing runs

**The idea:** one USB stick, any machine. You build the stick once, boot your own machines and your friends' from
it, and it measures each of them unattended — no installation, nothing written to their disks, the machine powers
off at the end. Every boot leaves one run folder on the stick; one stick collects runs from as many machines as you
like. How to build and use it: [`stick/README.md`](stick/README.md).

**Easiest — no git, just a browser:** open a [**Submit runs** issue](https://github.com/keysie/rigsim-benchmark/issues/new?template=submit-runs.yml),
drop a zip of the run folders from the stick's `runs/` folder into it and tick the three confirmations. A check
runs within a minute and comments on the issue; valid runs become a pull request automatically. Fix something by
editing the issue (e.g. dropping a corrected zip) — the check runs again. (The stick's data partition is Linux ext4:
copy the runs off it on a Linux machine, or on Windows from WSL with `wsl --mount`.)

**With git:** plug the stick into a Linux machine and run

```bash
git clone https://github.com/keysie/rigsim-benchmark && cd rigsim-benchmark
tools/contribute.sh /run/media/$USER/RIGSIM
```

It copies the runs that are not here yet, keeps the complete ones, commits them on a branch and opens a pull
request (with the [GitHub CLI](https://cli.github.com) logged in; otherwise it prints the two commands to push).

Every submission and pull request is checked automatically: it may only add new run folders under `results/runs/`,
each exactly as the stick wrote it (no other files, nothing edited), from a run that finished, with nothing
identifying in it. After
merging, the table updates itself.

**By sharing runs you agree that they are published under [CC BY 4.0](results/LICENSE)**, and you confirm that the
owner of every measured machine agreed to it.

## Layout

| Folder | Content |
|---|---|
| `stick/` | the measurement stick: image build, flashing, the on-stick orchestrator, its own probes |
| `bench/hw/` | the bench runner and toolkits the stick builds on (shared with rigsim's hardware bench) |
| `results/` | the measured runs (CC BY 4.0) |
| `predictions/` | rigsim's predictions per release and run (derived data, never recomputed) |
| `docs/` | the GitHub Pages site (`docs/data.json` is generated by `tools/index.py`) |
| `tools/` | `contribute.sh` (runs from a stick to a pull request), `submission.py` (zip submissions from issues), `validate.py` (the checks), `index.py` (the table), `measurements.py` (comparable values), `predict.py` (the daily rigsim run), `import.sh` (maintainer import) |
